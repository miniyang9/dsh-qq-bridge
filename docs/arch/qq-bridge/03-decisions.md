# 决策记录 · qq-bridge

一行一条。`否决了什么` 是给六周后的自己看的——它挡住的是把已否方案重新提出来。

| 编号 | 日期 | 决定 | 理由 | 否决了什么 |
|---|---|---|---|---|
| ADR-01 | 2026-10-24 | 边界主判据 = **数据所有权**：事实（turn / 审批 / 提问）归 DSH 会话日志；通信状态（待答点、投递记录、去重）归桥接。 | 只有一条事实来源时，"进度查询"和"重启恢复"才不会各算一套账。 | 否决"按变更频率切"作主判据；否决"按文件类型分目录即分层"。 |
| ADR-02 | 2026-10-24 | 跨层只有一种形状：`Event`。不跨层传"世界快照"。 | 快照会诱使每层各存一份可写副本；事件天然只读。 | 否决"核心维护一份会话状态镜像"。 |
| ADR-03 | 2026-10-24 | 桥接是**进程内 cordis 插件**，不是进程外 JSON-RPC 客户端。 | 两条接缝都在进程内 `ctx` 上；进程外是否暴露审批/提问仍待验证。 | 否决进程外 SDK 客户端（一期）。 |
| ADR-04 | 2026-10-24 | QQ 侧 WebSocket/鉴权只用 `src/transport/qq.js` 一处实现，便于替换。 | 长连、签名、重连属商品能力，但要能在 QQ 改版时换掉。 | 否决让传输细节渗进 router。 |
| ADR-05 | 2026-10-24 | 待答点与投递记录**落盘**（单文件 JSON + 原子写）。 | 崩、挂死、重启后必须知道哪些请求发过、哪些已答。 | 否决纯内存；否决引入嵌入式数据库。 |
| ADR-06 | 2026-10-24 | "进度"读 DSH 会话事件，桥接不维护影子状态。 | 会话日志已是权威，再造一份必然对不上。 | 否决"桥接自己统计 turn 与工具调用"。 |
| ADR-07 | 2026-10-24 | L5 骨架形态 = **正常**（沙箱真机一条最薄路径）。 | 后果成本中等，可回滚；真正昂贵的是正式机器人上线。 | 否决"只用假通道"。 |
| ADR-08 | 2026-10-24 | transport 不假设消息场景：单聊/群/频道只是字段差异。 | 写死单聊会让"单聊开通失败"直接变返工。 | 否决"一期写死单聊 openid"。 |
| ADR-09 | 2026-10-24 | ~~动作分档默认拒绝~~ —— **已被 ADR-12 推翻**，原文保留。 | 原意：未知动作按 high 处理只能拒。 | 否决"未知动作按 low"。 |
| ADR-10 | 2026-10-24 | 单实例单进程：一个桥接服务 1 个授权身份、1 条会话绑定。 | 与 frame F1/D3 一致。 | 否决多租户/多绑定（X1 二期）。 |
| ADR-11 | 2026-10-24 | 产品定位 = **控制面**：接管长任务的"等待"，把判断送回去；`/say` 续接已停会话在本期范围内。 | 人不答，agent 不会继续。 | 否决 v1 的"只监看 + 应答"；否决 X4「不向会话发消息」。 |
| ADR-12 | 2026-10-24 | **不做动作闸门**：任何动作都能在 QQ 上批；只做事实标注 + 审计 + `yes <id>` 确认。 | 用户明确要求"只提醒，不限制人类的同意"；提权/全局安装是日常操作。 | **推翻 ADR-09**；否决"高危只能回 PC 批"。 |
| ADR-13（已被 D19 取代） | 2026-10-24 | L2 = **只读旁路会话**（`headless` + `session-query` + read-only preset），显式触发、必须带依据。 | "必要的场景要能思考"，但监控器不该有写权限。 | 否决"把问题注入正在跑的会话"；否决"L2 自建检索"。 |
| ADR-14（已被 D20 取代） | 2026-10-24 | `/say` 只发给**已绑定**会话；发前回显"上次停在哪"；不新建会话/换工作区。 | 界线用结构划，不用意图划。 | 否决"从 QQ 派发新任务"（X4）；否决向运行中会话注入（X7）。 |
| ADR-15 | 2026-10-24 | 标注只陈述事实，**禁止风险评级措辞**（封闭五词表）。 | 一旦带评级，就会出现"这条危不危险"的争论。 | 否决"用颜色/等级区分危险度"。 |
| ADR-16 | 2026-10-24 | `PendingItem` → `WaitPoint`：把"审批/提问（阻塞）"与"turn 结束（空转）"统一为同一种等待。 | 两者对用户是同一种处境："它停下来了，等我"。 | 否决"待决实例 + 已停会话"两套实体。 |
| ADR-17 | 2026-10-24 | 实现语言用 **ESM JavaScript，包内无构建步骤**。 | 宿主直接加载 `lib/index.js`，宿主不编译；tsc 只会多一个"忘了构建"的失败点。 | 否决 TypeScript + tsc（一期）。 |
| ADR-18 | 2026-10-24 | **桥接不设审批超时**：生产不传 `timeoutMs`，审批无限等；`timeoutMs` 只用于测试夹具。 | 与 F11/D10/C1 一致：桥接替用户 settle 等于替用户自动拒绝。骨架期一度写了 120s 默认超时，被 arch 复审 R1-1 抓出撤销。 | 否决"给审批加超时以免一直挂着"。 |
| ADR-19 | 2026-10-24 | ~~`labeled` 用 `request.reversible` 代理~~ —— **S6 后作废（见 ADR-22）**，原文保留。 | S6 未跑，请求是否带参数仍未知（F18）；先跑通行为。代价：A11 只在代理上可验。 | 否决"等 S6 再实现标注"（会阻塞 S3/S5）。 |
| ADR-20 | 2026-10-24 | 多问题提问请求**让位**（返回 `undefined` → `next()`）。 | 批量提交语义下少答等于谎报"用户跳过"；让位后由桌面 UI 接，无人接则 `NO_PROVIDER` 报错。 | 否决"多问题时只答第一个"。 |
| ADR-21 | 2026-10-24 | 被动回复按 `msg_id` 记账、`msg_seq` 逐条递增，满 4 次转主动消息。 | QQ 对相同 `msg_id + msg_seq` 静默丢弃（HTTP 200），真机表现为"确认没到"。 | 否决"每条回复都用 msg_seq=1"。 |
| ADR-22 | 2026-10-24 | **审批请求不带工具参数**（实测：`{agent, toolName, callId?, reason?, displayReason?, signal}`）；标注判据要的参数按 `callId` 从会话 `tool/call` 事件反查，查不到就渲染"参数未附"。据此 **ADR-19 的 reversible 代理作废**。 | 真机与源码都确认请求体没有 args；`tool/call` 事件带 `arguments`，是唯一可靠来源。 | 否决"要求 DSH 改请求体加 args"（改上游）；否决"只按工具名白名单"（会把全局安装这类常规操作全标上） |

| ADR-23 | 2026-10-24 | **HTTP 200 不等于送达**：`msg_seq` 相同会被 QQ 静默去重；所有"发出去了"的验收必须带真机可见性检查。 | 真机上出现过"接口 200、手机上什么都没有"，而测试只断言了 outcome。 | 否决"接口返回 200 就当送达"（这是 S3 误判 PASS 的根因） |

| ADR-24 | 2026-10-24 | 所有会话类命令接受 **6 位短 id**（序号仍可用）。短 id = 剥离 `session-` 后的前 6 位。 | 完整 id 在手机上太长；序号会随 `/new`、`/wake` 漂移，短 id 稳定。 | 否决"只用序号"（漂移）；否决"只用完整 id"（难输入） |
| ADR-25 | 2026-10-24 | 卡片**合并窗口** `mergeMs`（生产 1500ms）：窗口内多张待答卡片合成一条。 | 兑现 frame C2（多事件合并成一条摘要），避免同一 turn 内三张卡片刷屏。 | 否决"逐条立即发"（BB-61 判不过）；否决"更长窗口"（拖慢 A1） |
| ADR-26 | 2026-10-24 | 通知文案扩展为 `[标题 · id6]` + `本轮 N 分钟：<摘要>` + 唤行动词。 | 只有"它停了"时无法定位是哪个任务、做了什么；标题+摘要是最小可用信息。 | 否决"只发状态"；否决"发完整日志"（超长且吵） |

| ADR-28 | 2026-10-25 | `/done` 后自动归档咨询会话（`workspaceController.archiveSession`）。 | 咨询会话长期占侧边栏；用户明确要求。 | 否决"仅隐藏"（文件还在） |
| ADR-29 | 2026-10-25 | 咨询会话按 `workspaceId` 创建并命名 `QQ 咨询 · <目标>`。 | 只传 cwd 会归"未分组"，无标题显示"未命名"。 | 否决"不显示"（GUI 里躲不掉） |
