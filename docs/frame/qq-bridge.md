# QQ 远程通道（DSH ↔ QQ）

一句话目标：**人不在 PC 前时，接管长任务的"等待"——看到它在等什么，把一次判断送回去。**

判据：离开 PC 6 小时后回来，能只靠 QQ 复述这 6 小时发生了什么、把卡住的决策解开；并且**不必回 PC** 就能处理不可逆动作——靠的是你把事实看全了，而不是靠系统替你拦。

> v1 的定位是"监看 + 应答"；**v5 改为控制面**：人不答，agent 不会继续；所以"把话送回去"本身是产品的一部分，不是附加项。见文末「版本变更」。

**T2。** 至少四个可独立验收单元：待答点发现与通知、答复回注、L2 问答、向 idle 会话续接（`/say`），再叠加通道与常驻部署。

### 4.1 标注规则（D9 的执行细则，不是闸门）

标注只回答**事实**，不做风险评级、不给颜色、不阻拦：

| 何时给标注 | 判据（可核验） |
|---|---|
| `sandbox_permissions` 出现在请求里 | 结构化字段，语义明确 |
| 工具名命中短白名单（≤5 条：删除、对外发送、发布/push、改远端配置） | 人为枚举、可复核；加一条要留记录 |
| 目标路径在工作区外且是写操作 | 参数原文可核验 |

其余一律不标。**默认 reversible。** 复用 `reason` 文本做动词匹配是被明确否决的（误报使人养成无视标注的习惯）。

命中标注的请求，其批准命令要求 `yes <id>`——这是**确认格式**（防误触），不是闸门：它不会因为动作类型而拒绝任何批准，只是要求你在回话里带上请求 id。

**适用范围**：本节决定两件事——卡片上标什么、以及这类请求的批准命令形式（`yes <id>`）；**不决定能不能批**。没有任何动作会因为命中本节而不被批准。

| 桥接崩了：审批立刻被拒，任务停摆 | 日志连续 fail-closed；`doctor` 失败 | 守护拉起 + 托盘本地告警 |
| 桥接挂死：进程在、心跳断，审批无限等 | 心跳超时 | 看门狗重启 + 重启后扫描悬挂待答点 |
| 官方审核没下来 / 单聊不可用 / 主动消息被关 | 发送返回权限错误 | 先沙箱验证；被动窗口当主策略 |
| 账号被盗 | **没有技术信号**：盗号者用的是你的 openid，白名单与审计只能证明"来自你的号"，不能区分是不是你 | 无技术缓解（D9 已接受该残余风险，见 C6）：只能靠你本人发现异常动作、改密码并下线 |
| L2 编了一个现场，你据此批了不可逆动作 | L2 回答里没有可核验的依据（事件 ID / 文件:行） | L2 无依据只能陈述事实；卡片标注"依据不足" |
| 你在手机上批错（选错选项 / 串了旧消息） | 审计里出现与上下文不符的批准 | `yes <id>` 强制带请求 id；答复与 id 不匹配一律驳回，不做任何状态变更 |
| 睡眠唤醒 / 直接断电 / 主动退出 | 时间戳断层；无痕 | 三种中断按 C3 分别处理 |

> 触发：远程场景下"重启后所有会话变未加载"，`/say` 无从下手。探针确认 DSH 有两条路：
> `createAgent(ownerCtx, { resumeSessionId })`（挂载已有会话）与 `createSession(request)`（新建会话）。

### 新增决策

|---|---|---|---|---|
| D15 | 唤醒 | `/wake <序号>`：把 `/list` 里「未加载」的会话**挂回当前进程**，不新建、不改工作区 | 中 | 只对已存在的会话 id 生效；挂载失败明确报错 |

## v7 增量：咨询通道（2026-10-24）

> 触发：`/why` 一次性问答不够用——问题通常要追问几轮才说清；且核对现场常常需要写点东西（跑个脚本、改个文件再验）。

### D18 咨询通道

| 项 | 约定 |
|---|---|
| 路由键 | **会话 id**。每条提问都自带目的地：`/why <id\|序号> <问题>`，不引入"当前在哪个通道"的隐式状态 |
| 生命周期 | 首次 `/why` 起一个**普通会话**（与 `/new` 同构）；再次 `/why` 同一 id 复用同一会话，保留上下文 |
| 结束 | `/done <id>` 手动结束；或 **300s 无新追问**自动结束 |
| 反馈 | 两种结束都必须回话，且带会话标识与轮数 |
| 可见性 | 咨询会话**不进 `/list`**（否则自己的提问会混进任务列表） |

### D19 咨询会话允许写

咨询会话**不设只读限制**——核对现场可能需要跑脚本、改文件。**这推翻了 ADR-13 的"只读旁路"**，代价是：

- 一次"提问"可能真的改动代码，而你在手机上看不到 diff；
- 因此咨询会话的**每一次写操作都要进审计**（ADR-23 同源），并在回话里附"本次改动了 N 个文件"。

### A19 改写

原 A19（"写类工具调用 0 次"）**作废**，改为：

| ID | 阈值 |
|---|---|
| A19′ | `/why` 的调查会话可写；但每次写操作都进审计，且回话里给出改动文件数与路径清单（布尔） |
| A34 | `/why 3 q1` 后 `/why 3 q2`：q2 的回答能引用 q1 的结论（同一会话，上下文连续，布尔） |
| A35 | `/done 3` 与 300s 超时：两种结束都回话，且都带"会话 3、共 N 轮"（布尔） |
| A36 | 咨询会话不出现在 `/list`（布尔） |

### 风险登记（已知并接受）

允许 QQ 触发的会话写文件，意味着**手机上一句话可以改代码**。缓解只有三条：审计、回话附改动清单、以及你自己的判断。这条与 ADR-12（不做动作闸门）是同一套安全模型的延伸。

### D20 发指令的目标也是显式 id

`/new` 之后要能对它说话，同样不能靠"当前绑定"这种隐式状态（和 D18 同一理由）：

| 形式 | 目标 |
|---|---|
| `/say <id\|序号> <文本>` | 明确发给那个会话（新建的、唤醒的、或任何空闲会话） |
| `/say <文本>` | 兼容形式：发给"上次 `/use` 或 `/new` 选中的那个" |

新建会话是**空上下文**：第一条 `/say` 就是它的任务描述，要写全（目标、边界、验收）。它会从头开始，不知道你之前在别的会话里聊过什么。

### D21 所有入站消息都是显式命令（取消隐式答复）

不带 `/` 的文本**不再有任何路由语义**，一律只回状态提示。答复也必须带格式：

| 命令 | 语义 |
|---|---|
| `/ans <id> <序号或文本>` | 答复待答请求：数字=选项，文本=自由回答（仅提问型） |
| `/yes <id>` | 批准（被标注的请求**只认这一种**，防手滑） |
| `/no <id>` | 拒绝 |
| `/why <id\|序号> <问题>` | 咨询通道（D18） |
| `/say <id\|序号> <文本>` | 给会话发指令（D20） |
| `/done <id>` | 结束咨询通道 |
| `/list` `/new [n]` `/use <n>` `/wake <n>` | 见前 |

推论（必须一起改）：

- **卡片提示要写全命令**，不能再写"回复 1"：改成 `改：/yes wp-3 批准 ｜ /no wp-3 拒绝 ｜ /why wp-3 看现场`；
- 旧的裸 `1`/`2`/`yes <id>` 一律不再识别，落入"未识别命令 → 回状态提示"；
- 验收相应改写：A2 的"回复选项"改为"发 `/ans <id> 1`"；A11 的"回批准不生效"改为"`/ans <id> 1` 不生效，只有 `/yes <id>` 生效"。
